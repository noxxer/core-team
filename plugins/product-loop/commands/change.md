# Задача

Изменение: $ARGUMENTS

**Цена называется до согласия, а не после работы.** Понятия и связи —
`.claude/knowledge/artifacts-map.md`; форма сметы — `references/radius.md`;
правила паспорта — `references/passport.md`.

## Шаг 0. Какой слой трогаем

Определи сам, не спрашивая, если видно из формулировки:

| Сказано про | Слой | Файл |
|---|---|---|
| как устроен мир, на что опираемся | **Утверждение** | `claims.md` |
| что продукт делает, кому, за сколько | **Паспорт** | `passport.md` |
| как выглядит и ведёт себя интерфейс | **Облик** | `design-system.md` |
| путь пользования, шаги | **Сценарий** | `scenarios/<имя>.md` |
| что система умеет | **Требование** | `spec/requirements.md` |
| что модуль обещает соседям | **Ответственность** | `spec/<продукт>/<зона>/<модуль>.md` |
| увиденное на экране | **вход снизу** — смотри `Шаг 1b` |

Не видно — спроси **одним** вопросом, а не тремя.

### Особый случай: паспорта ещё нет

Аргумент «паспорт» и файла нет → это не изменение, а заведение правды. Скопируй
`${CLAUDE_PLUGIN_ROOT}/templates/product-passport.md` в `project/passport.md` и
заполняй **разделами**: миссия → клиент → что делает → **границы** → состояние.
Раздел границ пустым не оставляй: без него любая идея формально уместна.
Дальше правки идут уже через смету.

## Шаг 1. Собери задетое — по названным связям

Вниз по цепочке правды: утверждение → паспорт (`holds`) → сценарии (`checks`,
`touches`) → требования (`from`) → ответственности (`covers`) → снимки (`deck`).

### Шаг 1b. Вход снизу — самый частый

Увиденное на экране идёт **вверх**: снимок → шаг сценария → ответственность → требование
→ возможно паспорт → в редком случае утверждение («мы обещали то, чего не можем»).
Механика та же, меняются только задетые узлы.

## Шаг 2. Разложи на три вида — это не задачи

| Вид | Что значит | Кто снимает |
|---|---|---|
| **снимается прогоном** | обязательство то же, надо переподтвердить | **машина, без человека** |
| **требует правки** | контракт противоречит новому родителю | исполнитель |
| **кандидат в долг** | расхождение можно оставить осознанно | человек, **с датой** |

Бо́льшая часть — первый вид. Шторм возникает там, где все три считают задачами.

## Шаг 3. Смета — до согласия

Форма — `references/radius.md`. Обязательны три честности: **нижняя граница** (собрано
по названным связям, значит «задето не меньше») · строка **«влияния открыты»** для
неразведённого · **дорогие прогоны отдельным числом**, не в общей куче.

И строка про потолок: сколько окажется в ленте «требует правки» и помещается ли это.

Три ответа: **принять · сузить · не сейчас**. Отказ — законный исход, а не неудача:
правка не вносится, и ничего не сломано.

## Шаг 4. После согласия

1. Правка вносится **в слой-источник**, а не туда, где расхождение видно.
2. Задетые узлы помечаются неподтверждёнными → `work/unconfirmed.md` (производное, руками не пишется).
3. «Требует правки» → `work/tasks.md`. «Кандидаты в долг» → `work/debt.md` **с датой и
   условием возврата**. Вопросы к человеку → `work/for-human.md` **с ценой бездействия**.
4. Если правка задела паспорт — разведи «Круги по воде»: карта влияний, ожидаемые правки,
   проверка, где реальность живёт по-старому. Не развёл — пометь «влияния открыты».
5. Косвенное снимается прогоном: `/plan-do` для тестов, `/deck` для снимков.

## Чего не делать

- Не превращать неподтверждённое в задачи целиком: большинство снимается прогоном.
- Не вносить правку, пока смета не показана. «Сделаем и увидим» — это и есть шторм.
- Не править слой, где расхождение **видно**, вместо слоя, где оно **родилось**.
- Не считать смету точной: она нижняя граница, и это говорится вслух.
