# Задача

Смотровая: $ARGUMENTS

Три режима. Пустой аргумент — **прогон и разбор**: это самое частое, и порознь они
почти не нужны. Прогон без разбора — потраченные минуты и каталог картинок.

| Режим | Когда |
|---|---|
| `init` | стенда в проекте ещё нет — разовая работа |
| `run <метка>` | снять ленту, не разбирая (например, перед долгой правкой) |
| `review <что>` | разобрать уже снятую ленту, не прогоняя заново |
| *(пусто)* | прогон, затем разбор |

Правила формы не пересказывай — они в навыке `smotrovaya:smotrovaya` и справочниках.

## Режим `init` — завести стенд

### Шаг 0. Чем проект уже гоняет браузер

**Не тащи вторую библиотеку.** Найди, что есть: Playwright, Cypress, Selenium, Puppeteer.
Нет ничего — предложи Playwright и **скажи цену вслух**: браузеры весят сотни мегабайт.

Нет фронтенда вовсе (библиотека, CLI, сервис без экранов) — **скажи прямо, что Смотровая
этому проекту не нужна**, и остановись. Точку `scenario-verification` закрывает то, что
предъявляет результат человеку; для сервиса без экранов это не снимки.

### Шаг 1. Три решения — одним `AskUserQuestion`

1. **Где живёт стенд.** Рядом с кодом, который снимает; каталог снимков — **вне git**.
2. **Первый сценарий.** Один, самый частый путь. Не «все» — первый.
3. **Дорогой путь.** Есть ли путь через платное или внешнее. Есть — он **не** входит в первый.

### Шаг 2. Каркас

`deck.ts` (класс сценария, проверки 1–4) · `scenarios/<первый>` · `run.sh` (прогрев, одна
метка на прогон, честный код возврата) · сборка индекса · `gallery.html` (лента, три
строки замечания) · `annotations.json` (поле человека «что смотрим») · `README.md`
с предусловиями этого проекта.

**Проверки 1–4 ставятся сразу:** дубль снимка, измеренная подпись, пустой экран, честный код
возврата.

**Версия снимка — пара (код, прогон), и код берётся из git.** У нового проекта коммитов может
не быть: стенд обязан пометить версию словом (`no-commit`) и сказать это вслух, а не упасть
с чужой ошибкой. Замер: на боевом прогоне первый запуск стенда лёг именно здесь. Без них лента врёт с первого прогона, и доверие теряется раньше, чем появится.

### Шаг 3. Доказательство мутацией

По каждому из четырёх: назови мутацию, внеси, покажи красный прогон, сними, покажи
зелёный. **Проверка, не виденная красной, — мнение.**

### Шаг 4. Точка подключения

Впиши в `project/connection-points.md`: `scenario-verification` → `smotrovaya`.

## Режим `run` — снять ленту

**Предусловия проверяются ДО прогона.** Замер: три «таймаута» оказались чужой правкой кода
посреди прогона; сценарий лендинга падал 3 раза из 4 на холодном стенде.

| Что | Если нет |
|---|---|
| приложение поднято | поднять: иначе весь прогон — ложные падения |
| дерево не будет трогаться | правки во время прогона рвут ленту (инвариант 7) |
| локаль стенда = локаль продукта | прибор исказит ровно то, что меряют (инвариант 8) |
| дорогие сценарии названы с ценой | «переснять всё» не должно случаться не глядя |
| внешние предусловия дорогих | падение по внешнему условию — не дефект кода |
| метка итерации | без неё прогоны неразличимы в ленте |

**Стенд — единственный на контур ресурс.** Идёт волна параллельных агентов — стенд
получает владельца в брифе.

Прогон: прогрев → одна метка на весь прогон → прогон → сборка индекса **при любом исходе**.

**После — три числа, а не «готово»:** сколько шагов из скольких и в какой версии ·
сколько дублей нашёл независимый скан (`md5`, а не код возврата проверки) · чего в ленте
нет (устройство без снимков, сценарий, не дошедший до конца).

## Режим `review` — разобрать ленту

### Шаг 0. Сверка на входе

Зелёный прогон **не** означает правды на экране. Назови: версию ленты · сколько шагов
сломано · что говорит скан дублей · сколько версий кода прошло с прошлого разбора.
Лента, снятая много версий назад, разбирается как исторический документ.

### Шаг 1. Дорожки в непересекающихся зонах

Раздели по сценариям или зонам; каждой — свой `deck-reviewer`, **только чтение**. Зоны не
пересекаются: иначе одна находка приходит трижды в разных словах. В брифе: что смотрим ·
где снимки · что уже известно (аннотации) · **куда пишет результат**, и приёмка называется
до запуска. Потолок — семь дорожек в волне.

### Шаг 2. Сведение в корни

Сырая находка — «подпись спорит с бейджем». Корень — **класс**, а не экземпляр. Находка
вида «источник не содержит того, что мы у него берём» — утверждение о классе: первым
действием поиск по всем репозиториям, **до** починки.

### Шаг 3. Разводка

уже случилось → **дефект** · закрывается постройкой → **требование** · только снизить →
**риск** · утверждение о мире → **утверждение** (`claims.md`) · выбор вариантов →
**решение** · построено разошлось с описанным → **неподтверждённое** · подпись шага врёт о
переходе → **дефект сценария**.

Дефект, уехавший в риски, получает вероятность, которой у него нет: он уже случился.

### Шаг 4. Правка в источнике

Туда, где ложь **родилась**, а не туда, где видна. Дальше — `/change` со сметой.
**«Мы знаем про это» закрытием не является.**

### Шаг 5. Отчёт человеку

Корни, а не список: что видно · где родилось · во что разведено · чем закрыть. И
отдельной строкой — **чего в ленте нет**.
