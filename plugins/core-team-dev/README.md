# Core Team Dev — ремесло разработки

**Роль остаётся в ядре, ремесло уезжает в плагин.** `dev`, `test`, `architect` — это контракты
участия в команде: кто с кем как работает, что пишет, что читает, чем отчитывается. Как именно
писать код — TDD, fail-fast, конвенции стека — их ремесло, и оно живёт здесь.

Закрывает точки подключения **`craft:tdd`**, **`craft:clarity`**, **`craft:stacks`**, **`planning`**
фреймворка [Core Team](https://github.com/noxxer/core-team).

## Зачем это отдельно

Ядро несло эти навыки внутри себя как **форки** чужих плагинов, и форки расходились с
источником молча: замер по строкам — 35 · 46 · 109 · 167 · 325. Форк не сообщает, что отстал;
он просто перестаёт быть тем, чем назывался.

Отдельный плагин снимает и вторую беду: проект, которому разработка не нужна (исследование,
контент, аналитика), больше не платит за неё контекстом каждой сессии.

## Что внутри

| Навык | Что даёт |
|---|---|
| `tdd-master` | Red → Green → Refactor, тест до кода, воспроизведение бага падающим тестом, справочники pytest и Django |
| `functional-clarity` | 22 принципа: fail-fast, запрет Error Hiding, минимальные зависимости, style guide, Python и Bash |
| `planner` | планирование в двух режимах — architecture (вход: README фичи) и execution (вход: ARCH); bootstrap памяти планировщика |
| `planner-reflect` | сверка плана с фактом после сессии, обновление `planner-context.md` |
| `stacks` | стек-справочники **по фазам**: backend Python, frontend React, дизайн API, OWASP |

| Команда | Что делает |
|---|---|
| `/plan-feat` | discovery фичи: user journey и критерии готовности |
| `/plan` | план исполнения в нужном режиме, NQD-гейт ≥3 альтернатив |
| `/plan-do` | конвейер ролей: architect → dev (TDD) → test (review) → keeper, цикл до чистого ревью |
| `/plan-reflect` | что план обещал и что вышло; обновление калибровки |

## Понятия, которыми владеет этот плагин

Лестница замысла — семейство **Работы**: у каждого есть номер, владелец и **признак
закрытия**. Закон семейства — в карте ядра (`.claude/knowledge/artifacts-map.md`).

| Понятие | English | Файл | **Закрывается, когда** |
|---|---|---|---|
| **Идея** | idea | `ideas/IDEA-NNNN.md` | назван исход: фича · поставка · **отказ** |
| **Поставка** | delivery | `deliveries/DEL-NNNN/` | **сценарий пройден насквозь** |
| **Путь развития** | roadmap | `roadmap.md` | не закрывается — правится, как паспорт |
| **Фича** | feature | `features/FEACLM-NNNN/README.md` | **у её шагов есть свежие снимки** |
| **Проект** | architecture | `…/ARCHITECTURE.md` | живёт одно изменение и умирает |
| **План выполнения** | execution | `…/EXECUTION.md` | теряет подтверждение, когда Проект сдвинулся |
| **Отчёт** | report | `…/IMPLEMENTATION-NN.md` | фаза закрыта чистой проверкой |

**Поставка закрывается сценарием, фича — снимками.** Раньше обе закрывались словом
«сделано» — и потому не закрывались никогда.

## Что осталось в ядре и почему

| Осталось | Причина |
|---|---|
| роли `dev`, `test`, `architect` | контракт участия в команде, а не способ писать код |
| их DPF (`knowledge/dpf/development.md` и соседние) | учебник ремесла роли читается активационным ритуалом, и гард целостности это проверяет: роль без DPF — тихий отказ |
| `knowledge/code-change-discipline.md` | 7 шагов перед правкой чужого кода инжектируются в **каждую** сессию хуком старта — это контракт, а не навык |
| выжимка Функциональной ясности в `CLAUDE.md` | правило команды действует и без плагина; здесь — полная версия на 22 принципа |
| правила `rules/stack-*.md` | канал доставки по `paths:` проектный: плагины `rules/` не поставляют (проверено на трёх маркетплейсах). Правило — **триггер**, содержание — навык `stacks` |

## Деградация, если плагин не подключён

Объявлена и произносится вслух, а не молчит: тесты пишутся после кода · планирование без
режимов и калибровки · конвенции стека **не выдумываются по аналогии** (аналогия выглядит как
знание) · ревью идёт по `knowledge/security-rules.md` вместо чеклиста OWASP.
