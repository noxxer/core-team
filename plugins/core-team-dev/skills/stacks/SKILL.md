# Стек-справочники

**Читается фаза, а не файл целиком.** У каждого стека три справочника — проектирование,
реализация, ревью, — и роль берёт тот, в чьей фазе она сейчас находится. Архитектор,
читающий чеклист ревью, тратит контекст на то, чем не занимается.

| Стек | Фаза | Справочник |
|---|---|---|
| **Backend Python** | проектирование | `references/backend-python/design.md` |
| | реализация | `references/backend-python/implement.md` |
| | ревью | `references/backend-python/review.md` |
| **Frontend React** | проектирование | `references/frontend-react/design.md` |
| | реализация | `references/frontend-react/implement.md` |
| | ревью | `references/frontend-react/review.md` |
| **Дизайн API** | проектирование | `references/api-design.md` |
| **Безопасность** | ревью, всегда | `references/security.md` |

## Как справочник доезжает до роли

В ядре Core Team лежат правила `.claude/rules/stack-*.md` с полем `paths:` — они приходят в
контекст **по факту касания подходящего файла** и называют, какую фазу читать. Правило —
**триггер, а не копия**: единственный источник содержания здесь, и разъехаться им нечем.

Замер, ради которого механизм устроен так: правило с путями доходит **и до субагента** —
роль-проба назвала кодовое слово правила, прочитав `.py`-файл, в котором его нет. Прежняя
схема держалась на обещании «роль сама определит стек и прочитает нужный файл».

## Если стек не определяется

Деградация объявленная: общие принципы Функциональной ясности (`functional-clarity`) и FPF.
Выдумывать конвенции незнакомого стека по аналогии — хуже, чем работать на общих принципах:
аналогия выглядит как знание.

## Безопасность читается всегда

`references/security.md` (OWASP Top 10) не привязан к стеку и входит в ревью любого кода.
Это единственный справочник, который берётся без вопроса о фазе.
