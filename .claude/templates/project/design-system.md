# Облик

> **Как продукт выглядит и ведёт себя.** Сценарий говорит, что делает человек;
> ответственность — кто это исполняет; облик — **как это выглядит**.
> Понятие и связи — `.claude/knowledge/artifacts-map.md`.

Это слой **правды**, а не задача: правка облика **снимает подтверждение со снимков** ровно так же,
как правка ответственности снимает подтверждение с тестов.

## 1. Токены

> Цвет, типографика, сетка, отступы, скругления, тени. Значения, а не описания:
> «основной текст — 16/24, −0.01em», а не «читаемый шрифт».

| Токен | Значение | Где применяется |
|---|---|---|
| | | |

## 2. Компоненты

> Что за компонент, из чего состоит, как ведёт себя при взаимодействии.
> Модуль фронта **ссылается** на компонент, а не описывает его заново.

| Компонент | Поведение | Ссылается ответственность |
|---|---|---|
| | | |

## 3. Пять состояний экрана

> **Проверяются на каждой фазе.** Экран, у которого описано только успешное
> состояние, не спроектирован — это не придирка, а самый частый дефект интерфейса.

| Состояние | Что показываем | Чего НЕ показываем |
|---|---|---|
| **loading** | | |
| **empty** | | |
| **error** | | |
| **success** | | |
| **partial** | | |

Имена состояний — те же, что в подписи снимка (`state`). Разъехались — снимок
перестаёт доказывать состояние, о котором говорит сценарий.

## 4. Тон

> Как продукт разговаривает: обращение, длина фраз, что называем своими именами,
> чего не обещаем. Сюда же — запреты (жаргон, англицизмы, восклицания).

## Связи

- **сценарий → облик:** шаг называет экран и состояние; состояние определено здесь.
- **облик → снимок:** снимок доказывает, что состояние выглядит как объявлено.
- **облик → ответственность:** модуль фронта ссылается на компонент.
- **правка облика → неподтверждённое:** снимки задетых экранов теряют свежесть.
