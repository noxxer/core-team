# Обратная связь фреймворку

> **Зачем.** У фреймворка отличный контур обучения **внутрь** проекта (DPF, память ролей,
> `planner-reflect`) и слабый — **наружу**. Замер на двух проектах: семь правил уровня
> фреймворка были дописаны в локальные `.claude/CLAUDE.md` и ни одно не вернулось в upstream.
> Одно из них было независимо переоткрыто вторым проектом два месяца спустя — то есть цена
> потери уже уплачена дважды.
>
> **Правило закрытия.** Запись закрывается **отправкой наверх** (issue/PR по
> `.github/ISSUE_TEMPLATE/feature_request.md`) либо явным «не поедет — вот почему».
> Пометка «мы знаем про это» закрытием не является.

## Куда что едет — три адреса

| Корзина | Что туда | Признак | Едет наверх? |
|---|---|---|---|
| **ядро** | верно независимо от стека и предметной области | нет ни имени технологии, ни слова домена | да — `knowledge/`, роли, гейты |
| **stacks/`<стек>`** | верно для технологии, не для ремесла | есть имя технологии, нет слова домена | да — навык `core-team-dev:stacks`, `references/<стек>/` |
| **project/dpf/** | предметное | есть слово домена | нет, остаётся здесь |

> Словесный критерий «нет слов предметной области» — **необходимый, но не отбирающий**:
> на 176 уроках он дал 132 кандидата при семи настоящих. Сильный сигнал другой —
> **проект уже дописал правило себе в файл фреймворка**. Такие места помечаются маркером:
>
> ```
> <!-- upstream-candidate: ядро — почему это верно для любого проекта -->
> <!-- upstream-candidate: stacks/backend-python — почему это верно для стека -->
> ```
>
> Собирает `bash .claude/hooks/collect-upstream-candidates.sh` (шаг Harvest в `/end-session`).

## Порог отправки

Назначает Founder. Ориентир: **≥3 открытые находки** либо **раз в 20 сессий** — что
наступит раньше. Реже — находки устаревают и теряют контекст; чаще — issue получается
из одного случая, а фреймворк принимает изменения по опыту, а не по случаю.
