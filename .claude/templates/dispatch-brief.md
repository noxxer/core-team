# Бриф субагента — форма задания

> **Бриф** — текст, который оркестратор кладёт в `Agent(subagent_type=<role>)`, отправляя роль
> работать. Не «кого позвать» (это таблица маршрутизации), а **что написать в сообщении**.
>
> Замер, из которого выросла форма: в боевой сессии дважды дефект брифа стоил дороже дефекта
> исполнения. Не назвал владение общим стендом — расколотый платный прогон. Не потребовал записи
> файла по ходу — **три дорожки из шести потеряли работу целиком**.

## Форма (копировать в сообщение агенту)

```
МОДЕЛЬ. <opus | sonnet | haiku> · усилие <low | дефолт | xhigh>
  Умолчание роли — из `.claude/knowledge/cost-model-discipline.md`. Называется ЯВНО:
  не названа — наследуется от родителя молча, и роль работает не тем классом.

ЗАДАЧА. <что должно стать правдой после твоей работы — одной фразой>

ЗАМЕР ПРЕЖДЕ ПРИЧИНЫ. <что измерить, чтобы причина стала известна>
  — либо: причина видна из <стектрейс / сообщение об ошибке / диф>, замер не нужен.

ЗОНА. Пишешь только: <пути>. Не трогаешь: <пути>.
  Общий ресурс <стенд / база / платный API> на время работы принадлежит <кому>.
  Имя берётся из `project/resources.md`, раздел «Единственные на контур».

ПРИЁМКА. <путь к файлу результата>
  Создай этот файл ПЕРВЫМ действием и дополняй по ходу. Не последним действием.
  Результат — состояние вне рабочего дерева (база, корзина, очередь, внешний сервис)?
  Назови его АДРЕС проверяемой строкой, не прозой: имя базы на узле:порту, ключ корзины,
  идентификатор очереди. И печатай цель записи ДО первого действия, а не описывай в отчёте после.

ГРАНИЦА. Не делаешь: <что за рамкой>. Точка остановки: <что считается «готово»>.

СВЕДЕНИЕ. <кто ещё судит об этом же объекте и в каком порядке сводим> — либо «никто».

ОТЧЁТ. Последний раздел — «Для памяти роли»: СРЕЗ СОСТОЯНИЯ по форме из твоего файла
  роли — фокус, устойчивое знание, открытые вопросы, решения, урок ремесла, отвергнутые
  пути, повторяющаяся ошибка, и первой строкой — прочиталась ли твоя память. Не «что сделано за сессию»: хроника дня живёт в
  `project/sessions/`, и приземление лентой хук не пропустит.
```

## Почему каждое поле

| Поле | Что ловит | Из какого замера |
|------|-----------|------------------|
| **Замер прежде причины** | бриф «почини X», где X не причина; агент добросовестно чинит не то | «фасилитатор пять раз назвал причину раньше замера» — каждый раз замер поправлял. Телефонный обрыв чинили в диалоге, а виновата была соседняя карточка сетки без `min-w-0` |
| **Зона** | гонки записи между дорожками | Express-Parallel: непересекающиеся зоны. Проверка идёт по **фактическим** путям, а не по заявленному владению: файл, отданный «в единоличное владение», писали все дорожки |
| **Общий ресурс** | расколотый прогон единственного на контур ресурса | стенд не был назван — TDD-дорожка дала 15 перезапусков за 20 минут и отравила платный живой прогон; у упавшего шага стало две неразличимые причины |
| **Приёмка** | потерю работы целиком — и результат, который цел, но лежит не там, где его ищут | три дорожки из шести; в другом проекте — большинство запросов ревью вернулось без отчёта. Файл, созданный первым действием, оставляет частичный результат даже при падении. Второй замер: отчёт дорожки был точен в каждом числе (24 обращения к площадке, пауза 20,8 с при объявленных 20), файл приёмки существовал и был непуст, гейт прошёл — а прогон писал в базу, заведённую сбоку, имя которой не было названо ни в команде, ни в отчёте. Соседняя дорожка проверила базу, где логично было искать, увидела пустоту, и оркестратор объявил основателю потерю работы, которая была цела; на выяснение ушли три сообщения и два запроса к базам. Отсюда строка про адрес состояния вне дерева |
| **Граница** | расползание задачи и правку «за компанию» | «правку распространять ровно туда, где ущерб доказан» — расширение уронило два чужих теста и сделало ещё два зелёными по неверной причине |
| **Сведение** | два вердикта об одном объекте без обмена | параллельные review и drift-sweep ратифицировали противоположное — лишний раунд |
| **Модель** | молчаливое наследование класса исполнителя | гейт 5 требует явного выбора при каждом диспатче, а поля для него не было ни в форме, ни в минимуме оркестратора: правило жило в `cost-model-discipline.md`, который читает `cto` — то есть не тот, кто диспатчит |
| **Отчёт** | инвалидация памяти роли | раздела нет → память роли не пополняется, и заметить это нечем. Просил «дата, что сделано» — то есть ровно ту хронику, которую запрещает форма блока в файле роли; бриф сильнее файла роли в момент работы, потому что он и есть сообщение агенту |

## Приёмка после волны

**Волна** — два и более субагента, запущенных параллельно; каждый идёт своей **дорожкой**.

```bash
.claude/hooks/check-lane-acceptance.sh --since <unix-время старта волны> \
  <приёмка-1> <приёмка-2> ...
```

Проверка идёт **по файлу, а не по отчёту агента**: отчёт бывает бодрым при потерянной работе.
`--since` отсекает наследие прошлого прогона — файл на месте, не пуст и при этом не менялся.

**`--since` обязателен, если приёмка дописывается в существующий файл** (глоссарий, реестр,
общий отчёт): без него такая приёмка зелёная и при полностью потерянной дорожке. Для нового
файла ключ не обязателен, но и не мешает. Проверщик печатает эту оговорку сам, когда ключа нет.

**Перед респауном упавшей дорожки — сначала приёмка.** Дважды упавшие агенты оставляли готовые
файлы, и респаун был бы дублем.

**Файл приёмки, рассказывающий о состоянии вне рабочего дерева, читается на адрес.** Прибор
проверяет непустоту и свежесть файла и слеп к тому, адресуем ли результат, о котором файл
рассказывает: приёмка без адреса при непустом файле остаётся зелёной по `check-lane-acceptance.sh`
— он этого не ловит, и здесь это честная граница прибора. Поэтому после прогона оркестратор
находит в файле приёмки строку с адресом (имя базы на узле:порту, ключ корзины, идентификатор
очереди) и идёт по ней сам; адреса нет — дорожка не принята, даже если отчёт точен в каждом числе.

## Когда НЕ применять

Одиночный lookup, чтение одного файла, заполнение шаблона по образцу — бриф вырождается в
«задача + приёмка», остальные поля не пишутся. Требовать полную форму там — ритуал.

Причина, видимая из стектрейса, не нуждается в замере: поле заполняется ссылкой на источник,
а не выдуманным измерением.
